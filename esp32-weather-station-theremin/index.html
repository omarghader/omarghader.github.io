Build an ESP32 Weather Station Theremin: A Photoresistor Music Instrument

August 11, 2026 · ESP32, weather-station, theremin, photoresistor, ESPHome, IoT, music-instrument, light-sensor, buzzer, DIY

Last weekend I set out to build a simple ESP32 weather station – the kind that logs ambient light and temperature – but somewhere between breadboarding the photoresistor and staring at an unused passive buzzer in my component box, the project evolved into something way cooler. Instead of just measuring light for a dashboard, I turned the sensor readings into pitch changes and built a rudimentary electronic theremin. The result is a smart weather station ESP32 that doubles as a musical instrument, all managed with ESPHome. If you’ve ever wanted to turn a light sensor into a playable synth, this is the guide you need.

Why a Theremin with a Photoresistor?

A proper theremin uses capacitance to detect hand proximity, but we can fake the core idea with a photoresistor: as you move your hand closer to the sensor, you cast a shadow that changes the resistance, which alters the voltage read by the ESP32’s ADC. Map that voltage to a frequency and feed it to a passive buzzer, and you’ve got a light‑controlled oscillator that reacts to your motions. Because we’re building on the foundation of an ESP32 weather station stack, everything you learn here can later be extended to a full‑blown environmental monitoring system – I’ll point out those upgrade paths as we go.

Materials & Tools

Before I dive into wiring and code, here’s what I used. The ESPHome ecosystem means we don’t need to write Arduino C++ from scratch; YAML does the heavy lifting.

  • ESP32 Development Board Module – ESP32-DevKit board: Buy it here (any DevKitC‑compatible board with ADC1 will work fine)
  • Photoresistor Module – the kind with an LM393 comparator gives both analog (AO) and digital output. We only need the analog pin today.
  • Passive Buzzer Module – a piezo element that expects a PWM signal, not a DC voltage. Most cheap modules include a transistor driver, but a bare buzzer with a 100Ω series resistor and an NPN transistor (2N2222) works too.
  • Breadboard and jumper wires
  • USB‑C or micro‑USB cable for programming and power
  • A PC with ESPHome installed (I’m using the ESPHome Dashboard add‑on in Home Assistant, but the CLI works just as well)

That’s it. No exotic capacitors, no op‑amps. If you’re missing a ready‑made photoresistor module, you can wire a CdS photoresistor with a 10kΩ resistor as a voltage divider straight to an ADC pin – I’ll mention that in the troubleshooting section.

Wiring the ESP32 Weather Station Components

I’ve mis‑wired ADC pins enough times to learn that checking the pinout diagram before plugging things in saves an hour of head‑scratching. The ESP32 has two ADC units; ADC1 is available even when Wi‑Fi is running, while ADC2 gets disrupted during Wi‑Fi activity. I always stick to ADC1 pins – GPIO32, 33, 34, 35, 36, or 39. For the photoresistor’s analog output I chose GPIO34, which is input‑only and perfectly safe.

For the buzzer, any GPIO that supports LEDC PWM will do; I used GPIO25 because it’s easy to remember.

Here’s the full wiring table:

ESP32 PinPhotoresistor ModulePassive Buzzer Module
3.3VVCC–
GNDGNDGND (shared)
GPIO34AO–
GPIO25–Signal/IN

If your buzzer module lacks a built‑in driver, insert an NPN transistor: base → 1kΩ resistor → GPIO25, collector → buzzer (+) & VCC 3.3V, emitter → GND. Without this, the ESP32’s pin can’t supply enough current, and your buzzer will barely whisper.

I once spent thirty minutes blaming ESPHome for a silent buzzer, only to discover I’d connected the module’s digital output (DO) instead of AO. Digital outs just give you zero or one – not exactly a sweeping pitch. Always double‑check which pin on the sensor module you’re using.

Software Setup

ESPHome is what turns our smart weather station ESP32 into a musical instrument without writing micro‑controller firmware from scratch. If you haven’t installed it yet, the quickest path is the ESPHome Dashboard in Home Assistant. I’ll assume you have a basic ESPHome environment ready – if not, the official getting started guide walks you through it.

Create a new device in the dashboard and name it weather-theremin. Before writing the YAML configuration, set up a secrets.yaml file inside your ESPHome folder:

# secrets.yaml
wifi_ssid: "YourNetworkName"
wifi_password: "YourSuperSecretPassword"

Then the device configuration (weather-theremin.yaml) can reference those secrets securely.

Configuration Walkthrough

Here’s the complete ESPHome YAML that transforms a photoresistor into a theremin. I’ll break down each section afterward.

esphome:
  name: weather-theremin
  friendly_name: Weather Theremin

esp32:
  board: esp32dev
  framework:
    type: arduino

# Wi‑Fi and fallback hotspot
wifi:
  ssid: !secret wifi_ssid
  password: !secret wifi_password
  ap:
    ssid: "Weather-Theremin Fallback"
    password: "fallback123"

captive_portal:

logger:

api:
  encryption:
    key: "your-generated-key"

ota:
  - platform: esphome
    password: "ota-password"

# Onboard LED to show Wi‑Fi status
status_led:
  pin: GPIO2

# Analog sensor reading light intensity
sensor:
  - platform: adc
    pin: GPIO34
    name: "Ambient Light"
    id: light_level
    update_interval: 50ms
    attenuation: 11db
    unit_of_measurement: "V"
    accuracy_decimals: 3
    filters:
      - multiply: 3.3   # scale raw 0-1 to voltage
      - sliding_window_moving_average:
          window_size: 5
          send_every: 1

# Buzzer output using LEDC PWM
output:
  - platform: ledc
    pin: GPIO25
    id: buzzer_pwm
    frequency: 1000 Hz

# Musical mapping: voltage -> frequency
interval:
  - interval: 50ms
    then:
      - lambda: |-
          float voltage = id(light_level).state;
          float freq = 100.0 + (voltage / 3.3) * 1900.0;
          // clamp to audible range
          if (freq < 50) freq = 50;
          if (freq > 4000) freq = 4000;
          
          // stop buzzer when brightness is max (hand away)
          if (voltage > 3.25) {
            id(buzzer_pwm).set_level(0);
          } else {
            id(buzzer_pwm).set_level(0.5);
            id(buzzer_pwm).update_frequency(freq);
          }

Wi‑Fi & Core Setup

The standard wifi block uses the secrets, and ap provides a fallback hotspot if your router is unreachable – crucial if you’re testing in a different room. captive_portal makes connecting to the fallback a breeze. The status_led on GPIO2 gives a quick visual: solid when connected, blinking when it’s hunting for Wi‑Fi. Without that LED, I once spent ten minutes thinking ESPHome didn’t upload, when really the board just hadn’t associated with my access point.

The Light Sensor

The ADC sensor reads the photoresistor’s analog voltage. I set attenuation: 11db so the ADC can measure up to ~3.3V with decent resolution. The multiply: 3.3 filter converts the raw 0.0–1.0 to actual volts. A sliding window average smooths out tiny jitter – otherwise even indoor fluorescent flicker can warble the pitch annoyingly.

Why 50ms update? Faster than the eye but slow enough to keep Wi‑Fi happy. If you try to read the ADC 10,000 times a second, you’ll starve the TCP stack and the device will drop offline.

The Buzzer & Pitch Mapping

The ledc output creates a PWM signal on GPIO25. The trick lies in the interval component: every 50ms we grab the sensor voltage and map it to a frequency between 100Hz and 2000Hz. When my hand is directly above the sensor (low light, low voltage), the pitch is deep and grumbly; as I pull away, the pitch climbs. I added a mute threshold – when voltage > 3.25V (nearly full brightness), the level goes to zero so the instrument only sings when you’re actively casting a shadow.

If you want an Arduino C++ sketch, the mapping is the same, but ESPHome’s lambda keeps everything inside one YAML file. I love that I can tweak the frequency range in the dashboard UI without re‑flashing.

Upload & Test

  1. Connect the ESP32 via USB and click “Install” in the ESPHome dashboard, or run esphome run weather-theremin.yaml from the CLI.
  2. Once uploaded, open the ESPHome logs (or the serial monitor) to check that the Ambient Light sensor publishes voltage readings.
  3. Open a browser to the device’s IP address (shown in logs) – you’ll see the web server interface displaying real‑time sensor values and the ability to manually test the buzzer.
  4. Move your hand over the photoresistor. The buzzer should warble up and down. If it’s completely silent, cover the sensor completely to drop voltage below 3.25V. No change? Check the mute threshold; maybe your ambient light is too low, so adjust the voltage > 3.25 condition.

I remember the first time I heard a swooping tone straight out of a 50s sci‑fi movie. The thrill of turning a weather station component into a playable instrument is hard to beat.

Troubleshooting Real‑World Gremlins

“Buzzer makes no sound”

First, confirm you’re using a passive buzzer, not an active one containing an oscillator. An active buzzer will just click. Measure with a multimeter – if it beeps on DC, it’s active. With a passive buzzer, ensure you’ve supplied a transistor driver. Temporarily test by connecting the signal wire directly to 3.3V; it should hopefully click, but not tone. Then test with a simple PWM script from the ESPHome web terminal.

“ADC reads 0V or NaN”

If the sensor shows 0V, you probably have the AO pin floating. Double‑check that the photoresistor module’s VCC and GND are connected, and that the module’s power LED is on. Some modules require a jumper to select analog mode – look for a tiny jumper cap.

If you built a bare voltage divider, ensure the photoresistor and fixed resistor form a proper divider between 3.3V and GND, and that the ADC pin connects to their midpoint. A missing pull‑down resistor can cause wild, unreadable values.

“Upload fails halfway”

ESPHome uploads over USB‑UART; the ESP32’s bootloader can be finicky if the board isn’t in download mode. Hold the BOOT button, press EN, release EN, then release BOOT – that’s the classic sequence. I once bricked a board by forgetting to release the BOOT button and somehow corrupted the bootloader, requiring a full reflash with esptool.py. If the upload hangs at “Connecting…”, check your USB cable can handle data (some charge‑only cables are evil). Also, try a different USB port – USB3 ports sometimes cause timing issues.

“Pitch sounds glitchy or motorboating”

The ADC’s noise can introduce low‑frequency modulation. Increase the sliding_window_moving_average window size, or add a small capacitor (100nF) between the photoresistor module’s AO pin and GND. That cleans up the signal without affecting responsiveness too much.

Enhancements & Next Steps

This core ESP32 weather station theremin is just the beginning. Because we’re using ESPHome, you can easily extend it into a multi‑sensor environmental station that also makes music.

  • Log light data to Home Assistant: The sensor already reports to the API. Build automations that record the light level and later overlay it on a Grafana dashboard – if you want alerting when the room gets too dark, my Grafana alerting custom message guide is a good starting point.
  • Add temperature and humidity: Plug in a DHT22 or the Aqara temperature sensor I used in my Zigbee2MQTT article. You can then play different pitch scales depending on temperature – a literal weather‑driven instrument.
  • Deep sleep for battery power: A 18650 cell with a TP4056 charger can run the ESP32 for hours if you put it to sleep when not touching the theremin. ESPHome’s deep_sleep component lets you wake on a touch pin.
  • Better sound: Swap the buzzer for an I2S audio DAC (like the MAX98357) and synthesize richer waveforms via the speaker component.
  • OLED display: Attach an SSD1306 to show the current frequency and voltage – but if the screen stays blank, remember my first temperature monitoring build where I accidentally swapped SDA and SCL. You can read that story in my ESP32 temperature monitor with Xiaomi Mijia article.

FAQ

Can I use a DHT22 instead of a photoresistor for this project?
You can use a DHT22 to read temperature and humidity, but a traditional theremin needs a continuous variable input. The photoresistor gives that smooth analog voltage; a DHT22 only updates once per second and returns digital values. However, you can combine both – map the temperature to a secondary effect like vibrato speed. For a proper smart weather station ESP32, I’d add the DHT22 alongside the photoresistor and log all three metrics to Home Assistant.

Why is my buzzer only producing a faint click when the light changes?
That’s a classic sign of using an active buzzer, which has a built‑in oscillator. Replace it with a passive buzzer and ensure you have a transistor driver circuit. If the hardware is correct, check that the ledc output’s frequency is being updated – visit the ESPHome web server and verify the sensor voltage changes and the buzzer command runs.

Can I make the theremin play specific musical notes?
Absolutely. Instead of a continuous pitch sweep, you can quantize the voltage to a predefined scale. In the lambda, you could define an array of note frequencies (e.g., C4=261, D4=294, E4=329…) and pick the closest based on the voltage. That turns your theremin into a light‑controlled arpeggiator.

How do I turn this into a regular ESP32 weather station?
You’re already 90% there. Disable the interval‑based buzzer mapping and keep only the sensor block. Add other sensors (BME280, BH1750) and the ESPHome API will stream all data to Home Assistant. You’ll have a fully functional ESP32 weather station with a light sensor, temperature, pressure, and humidity – no musical fugue required.

Why is my OLED display blank after I followed your wiring?
Even though this tutorial doesn’t use an OLED, I’ve been there with previous projects. Blank OLEDs are usually due to swapped I2C pins (SDA/SCL), missing pull‑up resistors, or not using the correct I2C address (0x3C vs 0x3D). Double‑check your board’s pin labels and scan the bus using an I2C scanner sketch. For a full walkthrough, peek at my ESP32 temperature monitoring guide where I painstakingly debugged the same issue.

Will this work with an ESP8266 instead of an ESP32?
Yes, but the ADC on the ESP8266 is only 1V max by default, so you’ll need a voltage divider or the attenuation: auto that ESP8266 doesn’t support as flexibly. The PWM output works fine, but the mapping will need different scaling. For the easiest experience, stick with the ESP32 Development Board Module – it has a much better ADC and more headroom.

Building a theremin out of an ESP32 weather station photoresistor taught me that IoT projects don’t have to end at dashboards. With a dash of ESPHome and a passive buzzer, you can turn environmental data into something you can hear – and play. Give it a try, experiment with motion, and if your cat learns to trigger the low note by walking past the sensor, well, consider that a feature.
